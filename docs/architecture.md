# Архітектура агента build-engineer

## Призначення

Агент автоматизує типовий наскрізний процес підготовки Java-проєкту: узгоджує Git-ігнорування, створює структуру застосунку, налаштовує Maven і JUnit 5, додає кросплатформний CI та перевіряє результат. Це зменшує кількість ручних кроків і допомагає виявляти помилки між етапами, наприклад відсутній виконуваний JAR або невдалий тест.

## Компоненти та взаємодія

| Компонент | Файли | Роль і взаємодія |
|---|---|---|
| Manifest агента | `.github/agents/build-engineer.agent.md` | Описує роль, обмеження, доступні skills і команди, правила безпечної роботи та критерії успіху. Спрямовує агента до відповідної команди чи skill. |
| Skills | `.github/skills/project-scaffold/SKILL.md`, `.github/skills/build-and-test/SKILL.md`, `.github/skills/github-actions/SKILL.md` | Надають детальні вимоги, вхідні параметри, безпечні правила створення/повторного запуску та перевірки для структури, збірки й CI. Команди відповідних етапів застосовують ці інструкції. |
| Команди | `.github/prompts/git-init.prompt.md`, `.github/prompts/create-project.prompt.md`, `.github/prompts/create-build.prompt.md`, `.github/prompts/create-actions.prompt.md`, `.github/prompts/check.prompt.md` | Реалізують окремі операції. Приймають задані параметри, перевіряють передумови й результат, а про невдачу повідомляють оркестратору через результат виконання команди. |
| Оркестратор | `.github/prompts/run-init.prompt.md` | Перевіряє передумови, задає сталі параметри, викликає команди в зафіксованому порядку та після кожного кроку вирішує, чи можна продовжувати. Завершує звіт результатом `PASS` або `FAIL`. |

### Skills

- **`project-scaffold`** — початкова структура Java Hello World, пакет `edu.lpnu.hello`, `App.java`, каталоги джерел і `docs`, а також базові дані README та `.gitignore`.
- **`build-and-test`** — Java 17, Maven, JUnit 5, `Calculator` і тест `BasicAddition`; очікуваний виконуваний артефакт — `target/hello.jar`.
- **`github-actions`** — скрипти збірки та GitHub Actions для Ubuntu, Windows і macOS, із завантаженням JAR як CI artifact.

### Доступні команди

| Команда | Призначення |
|---|---|
| `/git-init` | Перевірити або ініціалізувати Git і узгодити `.gitignore`. |
| `/create-project` | Створити початкову Java-структуру та застосунок. |
| `/create-build` | Налаштувати Maven, Java 17, JUnit 5 і `target/hello.jar`. |
| `/create-actions` | Налаштувати `ci.sh`, `ci.bat` і GitHub Actions CI. |
| `/check` | Перевірити файли, збірку, тест, JAR, CI та Git без виправлення проблем. |
| `/run-init` | Оркеструвати повне налаштування та фінальну перевірку. |

Команда `init` з файлу `.github/prompts/run-init.prompt.md` викликається як `/run-init` через конфлікт із вбудованою командою VS Code `/init`.

## Дані між етапами `init`

Оркестратор передає між командами фіксовану конфігурацію: мова `Java`, назва проєкту `hello`, пакет `edu.lpnu.hello`, Maven artifactId `hello`, JAR `target/hello.jar` і назву CI artifact `hello-app-${{ matrix.os }}`. Для CI також обов’язкові `ubuntu-latest`, `windows-latest` і `macos-latest`.

Послідовність і контрольні результати:

1. Перевірити доступність Git, Java 17 або новішої та Maven; зафіксувати початковий Git status, якщо workspace вже є репозиторієм.
2. Запустити `/git-init`; перед наступним кроком підтвердити Git-репозиторій, правила `.gitignore` та ігнорування `target/`.
3. Запустити `/create-project` із мовою та назвою; перевірити `App.java`, пакет, очікуваний текст, каталоги й README.
4. Запустити `/create-build` із назвою артефакту та пакетом; перевірити збірку, тест `BasicAddition` і виконання JAR.
5. Запустити `/create-actions` з шляхом JAR, назвою CI artifact і трьома ОС; перевірити скрипти та workflow.
6. Запустити `/check` і вимагати явного результату `PASS`.

Результат попереднього етапу використовується як умова переходу до наступного, а однакові параметри проєкту зберігаються протягом сценарію. Це не обмін довільними даними між файлами: кожна команда перевіряє конкретні файли й умови, визначені її prompt та відповідним skill.

## Обробка помилок оркестратором

`init` спершу перевіряє передумови й не запускає prompt-команди, якщо вони не виконані. Після кожної команди він звіряє статус виконання та очікувані результати. Перший збій або непідтверджена умова негайно зупиняє сценарій: наступні команди не запускаються, пропущені етапи позначаються як невиконані через попередню помилку, а загальний результат стає `FAIL`. Причину та доступні відомості про помилку потрібно вказати прямо; часткове виконання не подається як успіх. Конфліктні наявні файли не перезаписуються, а `init` не виконує commit, push чи `mvn clean`.

## Відмінності Java-варіанта від методички

| Елемент | У методичці | У цьому Java-варіанті |
|---|---|---|
| Виконуваний файл | `hello` | `target/hello.jar` |
| Каталог результатів збірки | `build/` | `target/` (стандартний каталог Maven) |
| Назва prompt-файлу оркестратора | `.github/prompts/init.prompt.md` | `.github/prompts/run-init.prompt.md` через конфлікт з вбудованою `/init` |

Артефакт створює Maven; його запускають командою `java -jar target/hello.jar`.
